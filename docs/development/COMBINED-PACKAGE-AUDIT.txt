New code and potential damage paths
- The only changed existing packaged files relative to the prepared position
  build are autoexec.sh (startup stages and exit-status trap) and the startup
  sender's two port-constant bytes. New files are the status sender and a
  32-hex build ID. The native Core/Now Playing/position library is byte-for-
  byte identical to the prepared candidate. The 18-file encrypted image was
  decrypted and matched against source and independent compiled ARM objects.
- New shell code reads a build ID and fixed readiness/process observations,
  remembers the first and last diagnostic message, and launches a finite
  outbound sender at exit. No added code writes firmware, bootloader, flash,
  settings, media database or an executable file on the deck. It does not
  listen for commands. Existing root-stage/lock cleanup still occurs first.
  Reports have an 8 KiB cap; the helper exits after at most twelve rounds.
  At most the startup and exit reporters can overlap during normal insertion.
- Existing core still modifies a guarded word in the RAM-backed rbp image,
  stages an ELF in RAM, restarts rbp, and installs guarded in-process hooks.
  It can disrupt playback if its assumed addresses, callback signature or
  player lifecycle are wrong. The unchanged native library has not been
  physically validated for position on this deck. This is the main remaining
  risk, and no source-only review can certify it away.
- The status trap runs on success/refusal and does read-only checks. A report
  may be absent if the device aborts the shell, the ISO disappears, or the USB
  network fails. A stage=complete report indicates shell completion; it does
  not prove healthy audio, correct position units, or durable recovery. Host
  packet counts and the operator's actual playback remain separate evidence.
- The existing rollback and stock boot path have limits documented in
  PACKAGE-SAFETY-AUDIT.txt. No firmware reflash, hot unload, remote installer
  or additional in-process hooks are introduced by this combined build.
